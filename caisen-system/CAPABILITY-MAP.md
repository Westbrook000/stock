# Capability Map: 蔡森量价股票分析系统

## 目标与当前基线

把现有的形态研究原型重构为可解释的股票与 ETF 分析系统：对每个标的和周期识别形态阶段，并给出买入、持有、卖出或等待建议及其证据。建议是研究辅助，不连接券商、不自动下单。现有本地行情、12 招规则卡、FastAPI 页面、人工复核和模拟接口作为重构基线；不预设必须推倒重写。

## 能力模块

| Module id | 职责 | 主要输出 | 依赖 |
|---|---|---|---|
| `source-rules` | 以项目内《多空转折一手抓》为主依据审计现有 12 招候选；仅把原书支持充分的规则纳入活动目录，逐项记录原文位置、正反例、候选/确认/失效定义和版本。把书中判断与工程阈值分开记录。 | 可追溯、带版本的活动规则及候选排除记录 | — |
| `market-data` | 管理当前股票和 ETF 行情文件的读取、字段规范、数据质量、来源与版本；生成日线和按交易周聚合的周线。 | 可审计的 OHLCV 序列和质量状态 | — |
| `pattern-engine` | 重构拐点、结构几何与 12 招状态识别；保留“即将成型/未确认”、确认、失效等因果状态，展示关键点和量价证据。 | 可回放的形态事件及证据 | `source-rules`, `market-data` |
| `decision-engine` | 综合形态方向、阶段、日/周冲突、数据质量与用户提供的持仓上下文，形成买入/持有/卖出/等待建议；说明触发原因、失效条件及参考价位。 | 面向单标的的可解释决策卡 | `source-rules`, `pattern-engine` |
| `simulation-validation` | 用 Backtrader 验收模拟执行与账目；不计交易费用。当前阶段检查撮合、订单状态和因果性，不做策略盈利效果验证。 | 可复核的模拟成交、持仓和验收结果 | `market-data`, `decision-engine` |
| `analysis-workbench` | 提供一键全量扫描、按买入适配度排序的结果、可点击直达的单标的详情、历史回放、人工标注/修正，以及模拟结果查看。 | 把当前最值得进一步考虑的买入标的排前，并从扫描一键进入其形态和买卖分析详情的本地工作台 | `pattern-engine`, `decision-engine`, `simulation-validation` |

## 建议构建顺序

`source-rules` 与 `market-data` 并行 → `pattern-engine` → `decision-engine` → `simulation-validation` → `analysis-workbench`。

## 端到端系统功能

用户从一个本地分析工作台完成“扫描 → 看形态证据 → 看买卖建议 → 回放/复核 → 模拟验收”的流程：

1. **行情范围与状态**：读取当前本地股票及全部 ETF 行情；以日线、周线分别分析。标明数据截止日、来源/版本和已知质量问题，缺数据或量价口径不明时提示数据不足。
2. **一键全量市场扫描**：用户点击一次“全量扫描”，覆盖本地全部股票和 ETF 文件、日线与周线；展示扫描进度和完成状态。结果按标的合并为一行，同时呈现日/周判断和冲突，不让同一标的重复占据多个排名位置。每行显示名称/代码、类别、决策状态和近期迷你 K 线图。
3. **买入优先排序**：默认将满足买入条件、当前仍有可执行空间的标的排在前面；候选之间按可解释的形态确认、量价证据、风险/目标空间、价格位置、数据完整性及日周关系排序。非买入项排在买入项之后，并显示是等待、持有、卖出或数据不足。排序是规则优先级，不是上涨概率；精确评分和并列规则由 `decision-engine` 规格定义。
4. **形态详情**：点击扫描行或迷你图直接打开对应标的详情，默认定位到最新行情，展示该股票/ETF的当前日线、周线形态和买卖分析。详情包括 K 线与成交量、关键拐点/颈线/整理边界、触发与失效位置、测幅目标、规则出处、逐项证据以及买卖理由/条件。形成中的候选必须显式标成例如“W底，未确认”，不得伪装成买入信号。
4. **买卖分析**：分别给出日线、周线判断及冲突提示；对形态证据足够的标的形成可解释的买入、持有、卖出或等待建议，附触发理由、参考介入/退出条件、结构失效位和目标。系统不输出未经校准的上涨概率。卖出与持仓、做空的精确定义由 `decision-engine` 规格明确。
5. **历史回放**：指定标的和历史截止日，页面只显示该日及以前可知的数据、形态和建议，用于检查判断是否使用未来数据。
6. **人工复核**：用户可接受识别、标为误识别、修正关键点并写备注；自动判断和人工修正各自留版本与来源。
7. **模拟执行**：将确认后的建议交给 Backtrader 在本地历史行情中模拟，展示委托/成交、持仓、现金及交易记录；按用户已确认的范围不计交易费用。此阶段验收撮合与账目，不验证策略盈利效果。
8. **运行边界**：本地服务/API，默认不接券商、不自动下单；系统输出研究辅助判断，由用户复核决定是否交易。

其中 `source-rules` 只负责原书规则来源和机器规则目录；它本身不会完成扫描、判断页面或模拟功能。每个后续模块在自己的规格中细化页面、接口和验收标准。

## 当前边界

- 沿用本地现有行情作为首版数据来源；历史缺口、复权和量能单位等质量限制须随信号显示。
- 覆盖股票、全部本地 ETF，以及日线、周线；两个周期分别判断并展示冲突。
- 识别系统先给可解释建议，不自动交易；本轮先完成形态校准和 Backtrader 模拟验收，策略效果验证另行安排。
- 形态规则、模型/算法候选和人工修正要能区分并追溯版本。

## 待在模块规格中确认

- “卖出”是否只表示对已有多头持仓的退出/减仓建议，还是还需覆盖做空及反向开仓。
- 没有账户持仓信息时，系统应仅给方向信号，还是提供条件式退出建议。
- 第一阶段重构是否保留当前页面与 API 形态，还是允许调整用户操作流程。
