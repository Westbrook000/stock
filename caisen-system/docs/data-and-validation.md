# 数据、模拟与验收

## 数据状态

导入根目录 `data/stocks/*.csv` 和 `data/etfs/*.csv`，映射中英文 OHLCV 列、按日期去重排序、检查OHLC关系。每次加载记录文件SHA256、末日、来源和内容指纹。现有 CSV 按 legacy 数据处理：复权口径、成交量单位、拆分/分红股数因子和退市历史均未验证。系统展示形态研究结果，但量能未验证时交易计划必须 `WAIT`。需要人工核验后才可在 `config/instruments.json` 添加标的；条目必须绑定文件SHA256，声明 `volume_unit_verified`、`corporate_actions_verified`、`tick_size`、`lot_size` 与ETF类别。更新CSV后旧核验自动失效。

行情导入会把相对前收盘价超过35%的隔夜跳空记为 `data_breaks`，并递增 `segment_id`。这只是保守的断点筛查：不会自动修复价格或成交量，也不能替代企业行动因子审计；合法极端行情可能触发，较温和的拆分/复权断点也可能漏过。形态的拐点、突破、回收和旗形窗口均不得跨段；周线会把同周的不同段分开聚合。人工确认后仍须在注册表中绑定来源文件哈希并完成价格、成交量和交易规则核验。

周线必须使用带版本的交易日历，并且源文件含有该周最后一个交易日后，才会生成正式周线。2020–2026 年周交易日直接使用 `caisen/data/xshg-official-closures.json` 中逐年记录的上交所官方休市公告；每年按全部工作日与官方休市范围构造，并对短周逐周测试。`exchange-calendars==4.5.6` 仅为 2000–2019 年提供预览日历：逐年对比发现该版本与官方公告在 2020、2025 存在不同，因此这些年份明确不用库数据生成正式周线。缺少最后交易日、`as_of` 截在周中、或超出官方公告覆盖年份时，只放入预览。2027 年及以后必须在官方年度休市安排发布并录入后才启用。日线可继续独立分析。

### 本地行情盘点（2026-10-24）

对本地文件做了一次完整只读盘点：发现 5,294 个 CSV（3,655 只股票、1,639 只 ETF），均可读取且至少有一条有效日线；均带有来源/成交量单位/企业行动或注册表核验告警，因为注册表为空且对应声明未绑定当前文件哈希。没有文件达到“无告警可用”状态；没有文件因格式或无有效数据而失败/不足；共剔除 4 条坏行情行。有效日期覆盖 1990-12-19 至 2026-10-16。该数量仅表示本地当前存续文件，不代表完整市场或历史成分。盘点过程中未修改 CSV。

用户的第二轮 10 个形态标签保存在 `calibration/labels/round_01_v2.user.json`。下述历史机器对照使用引擎 v14、规则集 `caisen-rules-v5`，结果仍保存在 `calibration/reports/round_01_v14.machine-review.json`；当前运行版本为 v15 / `caisen-rules-v6`，活动规则为十招，历史结果不重写也不与新口径混算。机器对照可用 `PYTHONPATH=caisen-system .venv/bin/python caisen-system/scripts/evaluate_calibration_labels.py` 重跑。v10 移除拐点 ATR 的未来值回填；若某 pivot 的 ATR 缺失或非正数则跳过。v11 将价格确认起点移到最后一个必要结构点的可知时间，早于形态可知时间的突破不再倒算成形态确认。用户后来明确 688216 的测幅目标无效即规则不成立，并澄清该截止日期没有任何书本形态。原始 v2 标签保留不覆盖，独立澄清记录改为 N；v14 增加 W 底两底差15%的开发阈值，日周均无当前候选。规则集 v4 增加左右肩价差不超过头部至颈线高度 7% 的头肩候选工程门槛；规则集 v5 再增加 W 底两底差上限15%的开发门槛，以筛除该批开发标签中的 N 误报；它不是书本规则，且需要独立留出验证。规则集 v3 引入 W/M 与收敛三角形结构段时长比不高于 2.5 的工程候选门槛；同样只来自用户开发标签复核。用户已明确 `N` 意为截至标注日期没有任何一招书本形态，形成中候选也算形态。比较器按时间语义理解状态：用户 `confirmed` 表示形态曾满足价格确认条件，即使后续已达目标、得到后续确认或在确认后失效仍算确认；`forming` 则只匹配截止日期仍处于形成中的候选。v14 将单独澄清合并后，十个开发标签对照为主形态 10/10、已标形态状态 6/6；样本用于开发调试，不是独立留出集，不作为准确率结论。另有一次将颈线外推越界改为人工复核警示的 v9 实验，主形态对照退化为 7/10，相关实验结果保存在 `calibration/reports/round_01_v9.machine-review.json` 供审计。240 例盲评、冻结留出集和前向观察仍未完成。

## 交易计划和模拟

买入计划固定结构止损，不为满足风险门槛移动止损；检查结构风险≤7%、首个未触达目标≥2R，并受现金/整手和可选20日成交量1%约束。扫描排序先放符合全部条件的买入候选，再按确认周期数、首目标R、结构风险、确认新鲜度和代码稳定排序。手续费、最低佣金和滑点默认均为零。看跌确认只显示“如持有可考虑卖出”的退出提示，不代表做空或自动下单。未验证的量能和交易规则作为风险告警显示，不会直接把基于当前数据的候选全部删除。

模拟入口通过 Backtrader 以因果下一根日K开盘撮合；交易费用和滑点为零；止损单先于首目标单提交，同日都触发时止损优先。买单仅在下一交易日开盘位于结构止损、首目标与最高允许价之间尝试一次，否则拒单；不重试。单笔使用整手现金可承受数量，首目标全额退出，未平仓部分按最后收盘价估值，现金与市值核对。周线信号仍通过日线行情撮合；只有已核验日历周参与信号。模拟报告用于验收订单与账目，不是回测盈利结论；策略效果验证已延期。历史窗口默认最近500根日线（周线取足够日线样本构造最多520周）。

## 正式验收路径

1. 每型由专家盲标正例及近似负例，样本按代码/相邻时间隔离；冻结规则后留出测试。报告准确率、召回、确认延迟、关键点误差及样本数。
2. 对任一信号截断在确认日重跑，再追加未来K线；过去的形态 ID、关键点、颈线和确认日不得重写，后续失效只能作为后续状态。自动测试覆盖追加未来K线稳定性及断点隔离。周线周中不确认。
3. 覆盖停牌/涨跌停/T+1与 ETF 回转差异、费用/滑点、跳空止损、拆分/分红量价断点、成交量单位、涨停无法买入与退市样本。
4. 报告按形态、周期、股票/ETF子类、市场阶段拆分净期望、盈亏因子、回撤、持仓日、拒单原因；另做冻结留出和30–60交易日前向观察。

用户可在详情页更新单个股票/ETF，或在扫描页触发全部本地标的行情更新。股票请求前复权日线；ETF代码按前缀补上沪市 `sh` 或深市 `sz` 后请求原始日线。覆盖前必须能解析旧文件，并确认上游包含旧行情中的每个有效交易日及完整日期范围；不完整响应在创建快照或改动元数据之前即拒绝，避免静默丢失历史。每个通过校验的标的先按哈希归档旧 CSV，再原子替换并记录新旧文件哈希、来源和日期范围；元数据提交失败时会回滚已替换的行情文件。2026-10-25 通过详情页分别真实更新 000001 与 510300：股票从 8,453 根增至 8,458 根，ETF 从 3,495 根增至 3,500 根；两者最新日期都从 2026-10-16 推进到 2026-10-23，旧 CSV 快照哈希已核验。更新成功不代表复权因子、公司行动或成交量单位已核验；批量更新仍可能被上游限流，系统不自动运行更新。

批量更新在启动前将本地标的清单写入 `refresh_job_items`，每只标的完成后只更新对应行；频繁变化的 `jobs.payload` 只保存任务摘要，不再重复序列化整个标的清单和累计结果。服务重启时，数据库里的遗留 queued/running 刷新任务会转为 interrupted。恢复任务会从摘要和标的行重建完整状态，沿用冻结清单，跳过已有成功记录，只重试失败或未处理的标的。页面启动时还会调用 `GET /api/v1/data/refresh/jobs`，因此即使浏览器会话存储丢失，也会显示可续跑任务。受控浏览器验收在重启后发现合成的 interrupted 任务；点击恢复后仅对不存在的本地代码做预检并返回失败，没有请求行情源。任务报告显示前20条结果，`GET /api/v1/jobs/{id}` 返回完整结果；所有单文件覆盖仍执行旧历史覆盖校验、快照与原子替换。真实单标的上游触发已验证；真实全市场限流及大规模长时运行仍未做，尚未对 5,000 多个文件执行全市场刷新。

这些数据表和人工复核接口已经为标注闭环留位；当前断点筛查只有隔夜跳空启发式。自动企业行动因子、完整类别注册、2000–2019 历史日历独立交叉核验、2027 年官方日历、240条盲标案例、指标报告和长期前向观察仍未完成。
