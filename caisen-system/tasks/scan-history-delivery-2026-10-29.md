# 扫描历史与规则验证交付记录（2026-10-29）

本文件为本轮追加记录，不替换既有 SPEC、计划或验收材料。

## 已确认的行为边界

- 扫描日期范围用于截取实际参与分析的行情。`date_to` 同时是观察日；规则所需的背景行情保留该观察日之前的完整可用历史，绝不带入未来数据。
- 形态搜索窗口为日线最近 500 根、周线最近 520 根。结构搜索条与历史背景分开传入；日/周线形态的长期质量背景都使用截至观察日的完整日线历史，绝不把周线聚合结果当作长期背景。
- 市场文件哈希只追踪本地行情文件快照。周线分析版本另由日线数据版本、日历版本和规范化周线内容共同追踪；删除旧刷新哈希逻辑不应删除分析版本追踪。
- 新扫描与历史查询分开。选择历史任务、修改筛选条件或翻页只读取已保存结果，不触发扫描。
- 历史记录保存任务参数、规则/应用版本、进度、库存摘要、逐标的结果、数据版本和错误。服务重启时 `queued`/`running` 任务标记为 `interrupted`，不自动续跑。
- 启动时将可识别的旧扫描 `jobs` 快照幂等导入规范化历史，保留原始 `jobs` 记录；不导入 `fixed_backtest`/`data_refresh` 或无法确认是扫描的记录。旧任务缺少的参数、版本显式显示未记录；失败计数优先使用保存的错误行/库存计数，证据不全时显示“失败数未记录”。
- 历史结果按原扫描买入优先顺序显示；允许按代码、名称、资产类别或行动另行排序。股票/ETF 筛选使用 `kind`，资产类别筛选使用类别字段。
- 历史结果组合筛选包括代码或名称、股票/ETF、资产类别、行动、多个形态和多个周期；每页 50 条。
- 全部标的分析失败时任务状态为 `failed`；只失败部分标的时为 `partial_failed`。两种任务均保留已写入结果并允许查询。历史结果页面须提示：打开标的详情会加载最新行情。
- 浏览器端统一检查 HTTP 状态并严格解析 JSON。纯文本 500 给出友好提示；`NaN`/`Infinity` 等非标准 JSON 不作为成功响应。
- 形态详情将结构时长、首次突破/观察日、历史低位百分比、前高回撤和质量门槛格式化为简明中文；未确认结构按观察日标记，内部 position-history cache 不显示。

## API 约定

- `POST /api/v1/scans` 创建任务。
- `GET /api/v1/jobs/{job_id}` 保留旧任务轮询兼容；旧 `jobs` 记录不会被伪造成带参数的历史扫描。
- `GET /api/v1/scans?page=N` 返回专用扫描历史，固定每页 50 条。
- `GET /api/v1/scans/{scan_id}/results` 支持 `q`（代码/名称）、`kind`、`category`、`action`、逗号分隔的 `pattern_types`/`timeframes`、`page`、`sort` 和 `order`。
- `sort=rank` 是默认顺序，对应扫描完成后的买入优先排序；`kind` 与资产 `category` 分开。

## 已批准的形态质量与回测约束

- 形态检测调用契约为 `detect_patterns(bars, ..., background_bars=None, structure_window=520)`。调用方传入尾部结构窗口（每日 500、每周 520 根）和同一观察日截至当日的完整背景；背景不可含未来数据。
- patterns 工作流当前规则实现报告为 `caisen-v16` / `caisen-rules-v7`。`w_bottom`、`inverse_head_shoulders`、`triangle_bottom` 需通过 `pattern_quality_pass`、有效突破和证据门槛；首结构 pivot 到首个颈线突破严格超过三个月，过早突破拒绝。低位证据按完整背景截至信号日计算：有效背景区间底部 30%，或形态前两年回撤至少 30%；没有有效区间时拒绝。bull flag 不新增此门槛。证据包括 duration、start、signal、first-break、low_position、prepattern_drawdown、pass。独立盲评包含 20 例：6 确认例、4 未确认例、4 短周期诊断、4 高位诊断、2 无买入形态输出；机器答案 sidecar 与盲评 HTML 分离。盲评文件为 `reports/pattern-blind-review.html` 与 `reports/pattern-blind-review.machine-answers.json`。已跑测试和静态样本检查，HTML 页面因本地 `file://` 打开被 CUA 拒绝而未做交互核验。
- 固定规则回测的账户初始资金固定 100,000，策略为固定止损 8%、止盈 20%，账户和周期彼此独立；runner 当前串行执行（`max_workers=1`）。周线任务也必须把完整日线行情交给 runner，由策略内部逐观察前缀聚合周线，并从日线上撮合下一交易日开盘。
- UI 默认“全部可用历史”；“快速验证：最近 300 个交易日”是用户显式选择。显式 `date_from` 只限制信号扫描/交易起点，不截断背景行情；`date_to` 截断观察数据，不读未来。
- 70% 切分日期用于描述已观察历史的开发/验证分组；它不是未触碰的独立留出集，也不得通过调整日期改变结果。所有绩效文字都应披露这一限制。
- 回测任务元数据、参数、进度、错误和输出路径持久化；唯一输出目录及逐账户 checkpoint 保留已完成账户。重启后活动任务标记中断，不自动续跑；已完成报告继续可读。历史 API 为 `GET /api/v1/fixed-backtests?page=N`、`GET /api/v1/fixed-backtests/{id}` 和 `GET /api/v1/fixed-backtests/{id}/report`。
- 可识别的旧扫描 `jobs` 在首次启动时迁移进 `scan_runs`/`scan_results`；一次性 `migration_runs` 标记避免重启反复解析大结果集。原始 jobs 不删除，固定回测/行情刷新/无法确认扫描类型的旧任务不迁移。旧参数或版本未知时显示“未记录”，所有失败行依然可查。
